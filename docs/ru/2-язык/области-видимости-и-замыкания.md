# Области видимости и замыкания

В DataCode замыкания работают через **копирование слотов при вызове**: при вызове вложенной функции или лямбды значения захваченных переменных копируются из фрейма родителя во фрейм вызываемой функции. Присваивания во вложенной функции **не записываются обратно** во фрейм родителя.

Чтобы поведение было предсказуемым (особенно при рекурсии и алгоритмах на графах), компилятор действует так:

## Правила

1. **Чтение разрешено.** Вложенная функция или лямбда может читать переменные из объемлющих функций (параметры и локали, объявленные через `=`).

2. **Присваивание во внешнюю переменную запрещено.** Если имя уже есть в области родительской функции, из вложенной функции или лямбды ему нельзя присвоить значение без создания новой локальной переменной (тени) — см. правило 3.

3. **Явная передача состояния.** Обновляемое состояние передавайте через параметры и возвращайте из функций (например кортежи вида `[visited, stack]`).

Обычное присваивание (`x = …`) внутри функции всегда относится **к этой функции**: либо к уже существующей локали/слоту захвата, либо создаётся новая неявная локальная переменная. Внешний фрейм при этом не меняется.

## Переменные цикла `for`

**Имя в заголовке** `for x in iterable { … }` (включая распаковку `for a, b in pairs`) — **блочная** область: действует только внутри этого цикла. После цикла имя недоступно следующим операторам той же функции.

**Присваивания в теле** цикла (например `elapsed = i`) по-прежнему относятся к **области функции** и остаются видимыми после цикла.

Поскольку имя паттерна не «утекает» во внешнюю функцию, вложенная функция **после** цикла может использовать то же имя без `let`:

```dc
fn build(freq) {
    for ch in freq {
        heap = push(heap, ch)
    }
    fn walk(node) {
        ch = node[2]   // новая локаль в walk, не внешняя переменная
        ...
    }
}
```

## Анти-паттерн

Не накапливайте состояние рекурсии через присваивание во внешние локали из вложенной функции:

```dc
fn bad(graph) {
    visited = []
    fn dfs(node) {
        visited = push(visited, node)
        ...
    }
}

```

Такой код даёт ошибку компиляции с текстом про присваивание во внешнюю переменную и предложением передать состояние явно или передать состояние явно.

## Рекомендуемый паттерн

Как в других примерах алгоритмов на графах (Косараju, компоненты связности): передавайте состояние параметрами и возвращайте обновлённые значения:

```dc
fn dfs(graph, node, visited, stack) {
    visited = push(visited, node)
    ...
    return [visited, stack]
}

```

## Замечание про `push`

`push(array, item)` возвращает значение массива, удобное для повторного присваивания; полагаться на «общую мутацию» через замыкания под текущими правилами ненадёжно. Лучше возвращать обновлённые массивы и кортежи состояния из вспомогательных функций.

## Будущее
