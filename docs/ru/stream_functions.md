# Потоковые функции (генераторы)

**Потоковые функции** (`stream fn`) позволяют приостановить выполнение, отдать значение вызывающему коду и потом продолжить **с того же места**. Удобно для ленивых последовательностей, конвейеров и **двустороннего** обмена: снаружи можно передать значение обратно внутрь функции.

Ниже — практическое руководство без лишней терминологии. Параметры, локальные переменные, `if` и циклы работают так же, как в обычной `fn`.

**Запустите готовый пример:**

```bash
datacode examples/ru/05-функции/потоковые_функции.dc
```

---

## Одной фразой

- Объявление: **`stream fn`**.  
- **`return expr`** — отдать **`expr`** потребителю (как *yield*), генератор **остаётся живым**.  
- **`ereturn expr`** — **завершить** генератор; результат читается через **`.final()`**.  
- Пошагово: **`.next()`**, **`.send(значение)`**, флаг **`.live`**.

---

## Как получить генератор

Вызов **`stream fn`** **не** выполняет тело до конца сразу. Возвращается **объект генератора**, который вы «крутите» циклом `for` или методами `.next()` / `.send()` / `.final()`.

```datacode
stream fn count_three() {
    return 1
    return 2
    return 3
}

gen = count_three()
# gen — генератор; тело выполняется по мере запроса значений
```

---

## Три способа «отдать значение» внутри `stream fn`

| Ключевое слово | Что делает | Кто получает значение |
|----------------|------------|------------------------|
| **`return expr`** | Пауза и **yield** `expr`. Генератор **жив**. | Цикл **`for x in gen`** или **`.next()`** / **`.send()`** |
| **`ireturn expr`** | То же по смыслу, но удобно строить сценарии с **`.next()`** и **`.send()`** | Вызывающий код через **`.next()`** / **`.send()`** |
| **`ereturn expr`** | **Конец** работы генератора, **`.live`** станет `false` | Только **`.final()`** — **не** следующее значение **`.next()`** |

**Подсказка:** **`return`** / **`ireturn`** — «вот очередное значение наружу», **`ereturn`** — «я закончил, вот итог для **`.final()`**».

---

## Простой путь: цикл `for`

Если нужны все значения по порядку — используйте **`for`**:

```datacode
stream fn nums() {
    return 10
    return 20
}

sum = 0
for x in nums() {
    sum = sum + x
}
# sum равен 30
```

Если поток завершился через **`ereturn`**, итог читается у **того же** объекта **`gen`**, что и в `for`, через **`.final()`** (см. ниже).

---

## `ereturn` и `.final()`

То, что отдаёт **`return`**, перечисляется в **`for`**. Выражение **`ereturn`** — **отдельно**: его возвращает **`.final()`** после завершения генератора.

```datacode
stream fn demo(short: bool) {
    if short {
        return 100
        ereturn 999
    }
    return 200
}

g = demo(true)
for x in g {
    print(x)   # 100
}
print(g.final())   # 999
```

Если **`ereturn`** не было, после завершения **`.final()`** обычно **`null`**.

---

## Методы генератора (шпаргалка)

| Член | Смысл |
|------|--------|
| **`.next()`** | Продолжить выполнение. Следующее значение **`return`** / **`ireturn`**, либо **`null`**, если генератор уже закончился. |
| **`.send(значение)`** | Как **`.next()`**, но если внутри ждут **`x = return expr`**, в **`x`** попадёт переданное **значение**. |
| **`.final()`** | После завершения — результат **`ereturn`**, иначе часто **`null`** до конца или если **`ereturn`** не было. |
| **`.live`** | **`true`**, пока генератор не дошёл до **`ereturn`** (или не закончил работу). Удобно для **`while g.live`**. |

---

## Двусторонний обмен: `ireturn`, `return`, `.send()`

Когда нужно **передать значение внутрь** приостановленной функции (аналог `send` в Python):

1. **`x = ireturn 40`** — при первом возобновлении наружу уходит **40**; переменная **`x`** заполнится тем, что подставится при возобновлении **следующего** ожидания на **`return`**.
2. **`ereturn x * n`** — используем уже подставленное **`x`**.

```datacode
stream fn scaled(n: int) {
    x = ireturn 40
    ereturn x * n
}

g = scaled(20)
first = g.send(10)   # снаружи видим 40; внутри x станет 10
result = g.final()   # 10 * 20 = 200
```

Если вместо **`.send()`** вызвать **`.next()`**, в слот подставляется значение с последнего yield (в духе «без отдельного send»). В учебном примере это даёт **`x == 40`** и **`final == 800`** при **`n == 20`**.

---

## Ручной обход: `while g.live` и `.next()`

Без **`for`** можно забирать значения вручную:

```datacode
stream fn steps(n: int) {
    x = ireturn 40
    d = return 50
    ereturn (x + d) * n
}

g = steps(10)
while g.live {
    r = g.next()
    print(r)
}
print(g.final())   # (40 + 50) * 10 = 900
```

Обычно: первый **`.next()`** — значение **`ireturn`**, второй — **`return`**, ещё один **`.next()`** может дать **`null`**, когда поток уже завершён; **`.final()`** при этом всё равно хранит результат **`ereturn`**.

---

## Ограничения (важно знать)

- Цикл **`for x in gen`** в сочетании с присваиванием **`x = return expr`** (режим yield-await) **не** заменяет сценарий с **`.next()`** / **`.send()`** — для двустороннего обмена ориентируйтесь на API итератора.
- **`.final()`** — это значение **последнего `ereturn`**, а не «сумма всех yield».
